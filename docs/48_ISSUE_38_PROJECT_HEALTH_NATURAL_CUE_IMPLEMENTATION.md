## 1. Рішення Product Owner

- **F1 «coordinator-evidence gate» відхилено.** Він дозволяв мовчки втратити другу частину змішаного запиту, яка не потребує інструментів. Приклад: «Як там Extract? І що ти думаєш, мені краще робити далі?». Мовчазна втрата наміру для Djonik неприйнятна. Інваріант не послаблюється.
- **Обрано F3 — natural withheld cue.** Семантика композиції не змінюється. Замінено лише текст, який бачить Daniel у стані `coordinator_withheld`.

## 2. Точна зміна коду

Змінено один файл runtime: `src/turnCorrelation.ts`. `src/djonikClient.ts` не змінювався: notice живе лише в `composeWithSpecialist`.

**Було** (`COORDINATOR_WITHHELD_NOTICE`):

```text
ℹ️ Джонік також сформував власний текст у цьому ході, але з подій не можна довести, що він не переказує й не суперечить висновку Project Health вище, тому його приховано. Чинний лише цей висновок. Якщо ви просили ще щось окреме (наприклад, план дня), надішліть це окремим повідомленням.
```

**Стало** (`COORDINATOR_WITHHELD_CUE`):

```text
Якщо в цьому ж запиті було ще щось — напиши це окремим повідомленням.
```

Інших змін у файлі два:
- у doc-коментарі `composeWithSpecialist` слово «notice» замінено описом cue;
- змінено ім'я константи в рядку, що будує `notice`.

Роздільник `\n\n———\n` між відповіддю спеціаліста і cue лишився. Він візуально відділяє системне речення від побайтної відповіді спеціаліста, щоб Daniel не прочитав cue як частину висновку Project Health. Цей самий роздільник уже використовують блоки мутацій.

Cue відповідає вимогам PO:
- українською;
- одне речення;
- без технічної лексики («координатор», «спеціаліст», «withheld», «runtime», «приховано»);
- без рамки помилки та emoji;
- умовне («Якщо…»): не стверджує, що друга частина справді була;
- робить можливу втрату явною;
- звертання на «ти», як у голосі Djonik ([managed-agents/djonik.md](../managed-agents/djonik.md) «How you speak»). Старий notice був на «ви».

Кращого формулювання не пропоную: запропоноване PO вже природне, коротке й відповідає конвенціям repo.

## 3. Машина станів: без змін

| Вхід (verified S) | Режим | Видимо |
|---|---|---|
| `C === ""` | `specialist_only` | S (з записами: `M` + блок S) |
| `C === S` | `exact` | S (з записами: `M` + блок S) |
| інший C | `coordinator_withheld` | S + `———` + **cue** (з записами: `M` + блок S + `———` + cue) |

Також без змін:
- verdict `unverified` → `DjonikSpecialistUnverifiedError`;
- `none` → звичайна відповідь;
- incomplete → `DjonikTurnIncompleteError`;
- unresolved write → `DjonikUnverifiedMutationError`;
- композиція work history.

Текст координатора в режимі `coordinator_withheld` не показується ніколи.

## 7. Залишкове обмеження (прийнятий UX-компроміс #38)

Чистий PH-хід **досі показує одне коротке речення-cue**, коли текст координатора відрізняється від відповіді спеціаліста. Live це стається завжди: 5/5 (docs/47 §3). Причини: координатор переказує відповідь і пише проміжні повідомлення, а провайдер не дає нативного provenance, щоб відрізнити переказ від незалежної другої частини.

PO прийняв це як UX-компроміс #38: краще одне природне речення в кожній PH-відповіді, ніж мовчазна втрата частини змішаного запиту.

Рядок prompt «Reply with the specialist's answer exactly as received…» лишається без змін. Прибирати його чи змінювати — окреме рішення поза цим кроком.
